# Folder Cleanup

为用户指定的文件夹制定有证据的清理方案，经选择后执行必要的关联修复，验证原有项目功能，并说明实际释放了多少磁盘空间。默认删除范围是当前对话的工作目录；用户自己创建对话，不需要替用户创建任务。清理完成的条件包括受影响的代码、配置、文档和文件关系保持一致。

## 1. 确定范围并只读扫描

- 用户明确提供路径时使用该路径，否则使用当前工作目录。先显示解析后的绝对路径。这里测量的是磁盘空间；若用户实际要解决 RAM/进程内存压力，说明区别并改用相应诊断流程。
- 当前目录为文件系统根、用户主目录或包含多个无关项目的宽泛位置时，先列直接子项供用户选范围，再对选定子目录深入分析；不要擅自全盘扫描或清理。
- 列出每个直接子项，包括隐藏项；文件夹的占用要包含其子树。缓存、环境、依赖、下载、日志、输出、数据和 checkpoint 都必须出现在清单中，不能因 gitignore 或大文件而排除。
- 不跟随符号链接，不进入其他挂载卷或网络位置。符号链接行写清链接本身的占用及指向；删除链接与删除其目标是不同操作。
- 优先使用本 skill 的只读测量脚本。先检查 `python3` 和 `du` 可用，再运行（`skill_dir` 是实际读到的本 skill 目录，`target` 是已核对的目标目录）：

  ```bash
  python3 "$skill_dir/scripts/inventory.py" --root "$target"
  ```

  脚本只输出 JSON：目录总占用、可用空间、全部直接子项、文件类型、链接信息及测量状态。它使用本机 `du` 测量 allocated KiB，不读取文件内容，不执行清理。没有 Python 时用本机 `du`、`find`/文件工具完成相同扫描；不为此安装软件。
- 测量失败、权限不足、扫描中变动时写“未知”或“部分测得”，并给原因；不能当成 0。保留所有行，不能用 `head`/top-N 代替完整清单。行数多时分表分页，继续直到全部列出。
- 从大到小排列。对于内容混合、占用较大或不能整体删除的文件夹，继续列其子项，直到建议能指向具体文件或目录。父项及子项是包含关系，预计释放空间不得重复相加。
- 明确口径：`du` 的占用是磁盘分配量的近似，不等于文件逻辑长度；APFS 克隆、压缩、稀疏文件、硬链接、快照和并发写入会影响最终可释放量。不要只看文件大小或 `ls -l` 推断收益。

## 2. 查清作用和删除风险

对每一行收集足够证据作出建议，不凭文件名、大体积或“搜索不到引用”直接判安全：

- 阅读现有项目说明、目录说明、依赖声明、入口和相关代码/配置引用；有 Git 时检查候选路径的 tracked/ignored/dirty 状态及必要的历史。
- 小文本文件读取必要片段；大文件/二进制优先看类型、元数据、manifest、创建来源和上下游。不要解压大归档或加载大型模型只为填表，也不要输出凭证内容。
- 区分可重建缓存、可重装依赖、临时文件、运行产物、原始数据、唯一结果/模型、源码、配置、备份和个人文件。环境/依赖只有在安装来源、锁文件和重建方法明确时才推荐删，并说明恢复成本。
- 原始/未发表数据、唯一 checkpoint、重要结果、备份、凭证、Git 元数据及现有 dirty/untracked 工作默认保留。只影响某个候选的风险不应阻塞其他明确安全且获批的候选；不强制用户先 commit。
- 对正在写入的日志/结果、数据库、应用数据、同步盘/iCloud 目录说明活动状态或跨设备删除风险。有必要时只检查候选的打开状态；停止作业或退出应用需要相应授权。
- 无法确认用途时写“用途未确认”及缺少的证据，建议“暂不删除/需用户决定”。“低风险”也要说明删除后会发生什么、怎样重建。

### 删除影响与关联文件检查

- 为每个候选建立最小影响链：**被删文件/目录 → 直接消费者或引用 → 间接影响的入口、功能和产物**。在风险列写出受影响的原目录及其他文件的绝对路径、影响方式、必要修复和核验方法；没有发现影响时说明检查范围，不能声称已经排除所有外部使用者。
- 按项目实际检查 imports、动态加载/插件发现、脚本入口、相对/绝对路径、配置默认值、软链接、构建/打包规则、测试夹具、资源/数据/模型加载、manifest/registry/checkpoint 索引，以及文档命令和链接。检查精确文件名、路径、模块/资源标识及通配符使用；一次文本搜索无结果不能证明无影响。
- 若选中的是项目子目录，允许只读检查已识别的所属项目及明确的其他消费者，包括父级说明、同级代码/配置和文档；这是影响分析范围，删除范围仍是选定目录。不要扩展为全盘扫描。
- 区分“可直接删除”“完成配套修改后可删除”和“删除会损失现有功能/唯一数据，应保留”。若能通过小范围修改维持行为，在风险列列明哪些代码、配置、文档、链接或索引需要更新；修复不明确、外部消费者未知或关键功能无法核验时建议保留/用户决定。
- 保持原有功能是约束：不能为了消除引用而删掉调用方、跳过测试、关闭功能、替换成占位返回值或伪造资源。功能退役、接口改变或改用其他数据/模型需要用户明确选择，不能包装为普通清理。
- 审计阶段为会影响运行的候选确定原有行为和最小验证方式，不启动会写入数据的测试/入口。用户批准方案后、执行清理前，运行合适的现有测试或入口 smoke test，记录基线失败并控制输出范围。缺少测试时可用真实最小输入验证受影响的路径；不能仅以语法通过或 grep 无引用证明功能正常。

## 3. 首次输出契约：五列表格

先用一句话写扫描目录、总占用、可用空间及完整/部分扫描状态，然后给表格。每行是一个真实文件或文件夹，列固定为：

| 绝对路径 | 磁盘占用 | 原本的功能作用 | 删除后的风险 | 推荐是否删除 |
|---|---|---|---|---|
| 实际绝对路径 | MiB/GiB；未知/部分时注明 | 具体用途和判断依据；未知明确写出 | 低/中/高 + 对原目录/其他文件和功能的影响 + 所需配套修改/恢复成本 + 检查证据 | 保留 / 推荐删除 / 配套修改后推荐删除 / 需用户决定 + 理由 |

使用真实测量值。路径可以是可点击的绝对文件链接；转义表格中的竖线、换行等特殊字符，但执行时使用原始路径字符串，不能复制显示用的转义作为命令。

表后给简短的完整操作方案：列出推荐删除的准确路径、去重后的预计释放量、清理方式、仍待决定的项目；需要关联修复时，同时列出要修改文件的绝对路径、具体改动及验证命令/行为。修改范围可以包含所属项目内的关联文件，但必须在方案里明确；另一个项目、共享配置或外部系统的修改需要明确范围，不能凭“顺便修好”扩大权限。即使用户最初说“按你推荐清理”，也先交付这份具体清单；获批对象必须能对应已展示的路径和配套改动。首次审计到这里结束，等待用户选择。

## 4. 按已批准的选择执行

- 用户在看到完整方案后说“按推荐执行”即批准表中明确的“推荐删除”和“配套修改后推荐删除”项及方案列出的必要关联改动；“需用户决定”项不在其中。用户点名的选择覆盖默认建议。对象和方式已明确时连续执行，不反复要求确认。
- 默认清理方式是可恢复地移入废纸篓。明确说明：移入同一磁盘的废纸篓通常不会立即增加可用空间。用户明确批准永久删除或清空这些指定条目时才做永久删除；从不清空整个废纸篓。
- 已有用户授权覆盖具体路径和永久删除方式时直接执行，不再重复询问。只有路径、处理方式或风险存在实质性缺口时问一个简短问题。
- 执行前重新核对每个路径、类型、大小、链接/挂载状态及影响。目标必须在已确认目录内，且不能是目标目录本身、根目录或主目录。遇到新产生的数据、dirty 工作、路径替换或用途不符时，暂停该项并更新建议，继续其他已批准项。
- 清理子项时只处理获批的那些子项，不能因此删除整个父文件夹。使用准确的绝对路径和安全 quoting；发现时的 glob、通配符、模糊名称和未经核对的环境变量不能直接作为删除目标。
- macOS 有 `trash` 时可用 `trash "$approved_absolute_path"` 逐项移动，核对退出结果并记录恢复方式。若使用其他可恢复方式，记录原位置和实际目的地；不覆盖同名文件。工具失败后不能自动改为永久删除。
- 不在同一磁盘创建整目录 tarball/副本来“省空间”；如确需备份到其他位置，先确认备份目标和可用空间。
- 把删除与必要修复作为一个完整变更执行：更新代码/配置的有效路径或加载方式，移除已退役产物的索引条目，修正文档中的实际命令/链接，并保留可恢复的原状态。使用最小补丁，保留用户原有 dirty 改动；不能只删文件，把关联修复留作“建议”。
- 优先可恢复地移开候选并完成修复，再在候选已不可从原路径读取的条件下验证；测试若依赖缓存重建，也要覆盖缓存缺失后首次运行。永久删除已获批时，将不可逆处理放到受影响功能验证通过之后；记录能准确还原的原路径、移动目的地和本次修复。
- 若关联修复或验证失败，不把该项标成清理完成，也不永久删除它；恢复可恢复的候选并撤回本次相关补丁，保留用户已有改动，说明失败点。继续处理不受影响的获批项；禁止用 `git reset --hard` 或整文件覆盖来回滚用户工作。
- 不做与清理无关的重构、不强制创建 `utils/` 或交接文档、不变更 Git 历史，也不擅自清理目录外的系统缓存、应用或快照。现有项目文档因本次清理失效时应同步修正。

## 5. 核验和交付

重新测量目标目录和所在卷可用空间，核对所有已批准路径的实际结果。逐项记录成功、失败、保留及恢复方式；不能将一次命令成功当成整批完成。

完成前在已识别项目范围内重新扫描残留引用，核对配置、manifest/registry、文档及链接，然后运行与影响链对应的测试、构建或真实最小入口，比较清理前基线。覆盖运行/导入/资源加载等受影响行为；只搜引用、只 lint、只编译不足以证明这些行为正常。无需运行无关的昂贵测试；未覆盖的关键行为要具体说明，不能宣称项目完全可用。

最终简短报告：处理了哪些路径、配套修改了哪些文件、受影响功能的验证结果、处理方式、占用/可用空间前后变化、恢复途径和未完成项。移到废纸篓的字节数属于“可恢复地移走”，不能冒充已释放空间；快照或其他进程使可用空间变化难以归因时如实说明。

## 与其他 Skill 的边界

- `wrap-up`：暂停开发、整理代码并保留恢复工作所需的交接上下文。
- `folder-cleanup`：评估一个目录内文件的磁盘占用、用途和删除影响，按用户选择清理、完成必要关联修复并验证功能。
- `mac-app-uninstaller`：围绕指定应用核对应用包、后台项及目录外残留。
